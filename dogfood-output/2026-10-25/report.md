## 发现

### ISSUE-001：常用“帮忙”动作的弹窗成本高于即时回报

- 严重程度：medium；类型：UX / 玩法优化建议，不是功能故障。
- 实测：第 1 天正常营业，点击“选择帮忙”，游戏暂停、整个房间模糊，弹窗此时仅有一个动作“加快制作”，效果是每位正在制作的员工节省 0.3 秒。需要再点一次才能恢复看店。成功后有“吧台手加快了节奏”的文字提示。
- 复现：开店并等店员开始制作 → 点击右下角“选择帮忙” → 选择“加快制作”。
- 证据：[营业](screenshots/04-day1-open.png)、[帮忙弹窗](screenshots/06-help-dialog.png)、[操作反馈](screenshots/07-after-help.png)；[完整过程录像](videos/day1-play.webm)。
- 影响：玩家想参与一个轻巧动作，却要打断对店铺的观察。只有一个可用动作时没有实质选择，0.3 秒的数值回报也难以直观看出。
- 建议：单一可用动作直接执行，多个动作再展开轻量菜单；把反馈放在咖啡机/员工头顶，以进度跃进、蒸汽或短促动作体现。是否增强收益应通过后续试玩验证。
- 第3天复查：帮忙确实会出现排队选择，因此不能说全程只有一个动作。但有一项写“让 美式咖啡 排到最前”，说明却是“当前排位第1 · 增加8秒耐心”，把顾客写成饮品且已是第一还强调移到最前。建议显示顾客头像/订单，并对队首改称“安抚等待的客人（+8秒耐心）”。[第三天选项](screenshots/35-help-later.png)、[执行后反馈](screenshots/36-queue-help-result.png)。

HTTP Tailscale 地址上显示“临时咖啡馆：本次进度不会保存”，因此本次主流程在一个会话内连续游玩。它不是已经证实的正式 HTTPS 发布版存档故障。录像工具首次开始会重建浏览器上下文，因此录制前引导被重置；该工具副作用不计为游戏缺陷。

### ISSUE-002：桌面开店指南与经营面板互相遮挡

- 严重程度：medium；类型：visual / UX。
- 实测位置：1440×1000，第1天营业中开店指南处于4/6，打开右下“管理”，再打开“菜单”。指南仍悬浮在右侧桌位附近，右半部分被经营抽屉覆盖；仅打开快捷菜单也会与其争抢位置。
- 复现：完成首单 → [主场景出现第4步指南](screenshots/07-after-help.png) → [展开管理快捷菜单](screenshots/09-management-shortcuts.png) → [进入菜单抽屉](screenshots/10-menu.png)。[过程录像](videos/day1-play.webm)。
- 影响：原本用于解释下一步的引导成了被挡住的背景卡片，同时占住店内角色与桌位的观察空间。
- 建议：打开经营抽屉时暂时折叠引导，只保留一个小进度入口；关闭抽屉再恢复。避免在房间中央/桌位叠加说明卡。

### ISSUE-003：菜品卡把当前数据与升级结果塞在同一行

- 严重程度：low；类型：visual / 经营决策易读性。
- 实测：浓缩卡出现“售价 $3 · 原料 $1 · 1.2秒 · 售价 $3 → ≈$6.53”，另有金额详情、可做份数、味道熟练度、在售与升级按钮。数字齐全，但新玩家不易快速回答“现在赚多少、升级改变什么”。
- 证据：[初始菜单](screenshots/10-menu.png)、[解锁第二种咖啡后](screenshots/17-unlock-americano.png)。静态问题，录像不适用。
- 建议：第一行显示售价/每杯毛利/制作时间；升级区域单列“升级后售价、增量、所需金额”。次要精确小数留给详情，保持可核对。

### ISSUE-004：手机备店页把可选支线放在缺货和补货之前

- 严重程度：medium；类型：UX / 信息层级；建议优先修改。
- 条件：390×844，正常完成第一天，与米娜相遇后，解锁并上架美式，进入第二天准备菜单。
- 实测：经营风格与米娜心愿占首屏约300px；缺咖啡豆43份与“备足一天所需·$43”在下方需要滚动。“开始营业”却固定在底部可见。
- 证据：[手机备店首屏](mobile/screenshots/12-day2-prep.png)、[桌面同一备店内容](screenshots/18-day2-prep.png)。静态布局问题，录像不适用。
- 影响：新手第一次独立备店，容易先开门再发现原料不够。此次已正确补货，并未造成真实缺货损失。
- 建议：把库存健康、补齐金额和补货按钮贴近开门操作；把支线卡压为一行邀请并允许展开，仍保留它的温度。

### ISSUE-005：共享库存的单品上限容易被理解成总可售份数

- 严重程度：low；类型：content / UX。
- 实测：浓缩与美式各写“库存可做13份”，二者均消耗豆子×1，实际共用13份豆子。补货43份后，两者同时变为56份。短缺提醒仅点名美式。
- 证据：[备货前](screenshots/18-day2-prep.png)、[手机两行库存](mobile/screenshots/12-day2-prep.png)。静态文案问题，录像不适用。
- 判断：每行单品上限本身并非计算错误，但用户要自己推断共享关系。
- 建议：注明“共用13份咖啡豆，合计最多13杯”；短缺提醒优先按共同食材解释。

### ISSUE-006：手机营业主画面不显示正在使用的倍速

- 严重程度：low；类型：UX / 状态可见性。
- 实测：更多菜单里4×有选中态，关闭后主界面只见时钟，没有当前倍率。
- 静态证据：[更多菜单选中4×](mobile/screenshots/14-selected-speed.png)、[营业主画面](mobile/screenshots/15-speed-hidden.png)。这是持续状态的视觉缺失，未声称切换行为失效。
- 建议：时钟旁常显1×/2×/4×，点击时钟继续复用现有速度入口。

## 画面和玩法方向（主观建议，不另计缺陷）

1. 保留现有暖色咖啡馆、像素家具、窗外景色和顾客走动。画面最急需的是信息避让，而不是全面重画素材。
2. 熟客故事有具体生活细节，例如米娜练习讲解步行地图、西奥固定通勤。对话目前是一段文字加按钮，可以复用角色头像和章节标题，让玩家更容易把“这个故事”与“刚才那位客人”连起来。证据：[西奥故事](screenshots/08-story.png)、[米娜故事](screenshots/32-mina-story-dialog.png)。
3. 早期主动参与的收益要更清楚：单动作帮忙直接执行，把反馈落在场景里；有多个方案才展开选择。可让玩家更早稳定体验一次口味推荐/照顾熟客的结果，避免用强制连点或惩罚来制造忙碌。
4. 第3天客群、菜单覆盖和资金周转已有策略价值。第3天结算已经显示“招待最多的是通勤客，成功服务34位”及客群明细，方向正确；可继续把本日新饮品与相应客群的变化说得具体。现有收入、成本和明日补货建议应保留。
