# 画面与信息层级独立复核

复核日期：2026-10-25。最初仅检查本次真实试玩截图，随后针对第一项另开隔离浏览器做稳态交互复核。全程没有读取游戏源码或修改内部状态。

## 最值得先改的两处

### 1. 桌面引导卡与管理浮层相互遮挡

**优先级：中。观察事实。**

- 在 1440×1000 的营业画面里，展开的“开店小指南”盖住右侧桌椅和活动区域的一部分。见 [07-after-help.png](screenshots/07-after-help.png)。
- 打开右下角管理快捷菜单后，竖直菜单叠在已折叠引导卡的右半侧。见 [09-management-shortcuts.png](screenshots/09-management-shortcuts.png)。
- 进一步打开经营手账时，引导卡向左移，但仍从约 x=670 延伸进从约 x=905 开始的抽屉底下，卡片右半截不可见。见 [10-menu.png](screenshots/10-menu.png)。这比单纯“界面有些多”更具体：同一时刻的两个导航/引导组件没有完全避让。

**建议：** 打开经营手账或快捷菜单时，暂收引导卡，关闭后恢复；平时让指南留在固定边缘区域，展开内容避开两张桌子。当前引导文字和绿色进度已有足够辨识度，不必重新设计整套外观。

**稳态复核：** 已用独立新店、1440×1000 视口重现，每次打开菜单或抽屉后等 2 秒，并再次等待确认，遮挡仍存在。[复现报告与录像](overlap/report.md)。主 HUD 仍有另一个“打烊结算”，因此不是核心流程阻断；未使用强制点击测试隐藏按钮。

### 2. 菜品卡混合展示“当前经营数据”和“升级后的预告”

**优先级：中。观察事实 + 信息设计判断。**

- 桌面和手机菜品卡均把“售价 $3 · 原料 $1 · 1.2秒 · 售价 $3 → ≈$6.53”挤在一行，两个“售价”之间只有点号，必须读完整句才能知道哪个是现在、哪个是升级后。
- 下方还同时出现“还差 ≈$62.6 / ≈$86.6”、味道、已售数量、下一档分数、进度条和底部“升级 ≈$89.6”。新手第一次查看时，需要自己把这些分散的数字组织成一次升级的价值判断。
- 证据：[桌面菜品卡](screenshots/10-menu.png)、[手机菜品卡](mobile/screenshots/05-management.png)。手机实际上仍有较多纵向空白，因此没有必要压成长句。

**建议：** 当前状态单独一行，例如“售价 $3｜每杯成本 $1｜制作 1.2秒”；升级按钮上方单独写“升级后售价约 $6.53”。把资金缺口贴近升级按钮，把熟练度及味道成长留成另一组。“每杯毛利增加多少”可以作为辅助，但需确认原料和配方规则后再决定是否展示。

**复核边界：** 这不是数值错误。是否保留小数精度是玩法经济显示的选择，不宜仅为了好看擅自改变实际价格。

## 建议保留

- **室内整体美术。** 木柜、奶油墙面、绿毯、红格窗帘、黑板和暖灯的配色统一，足以形成咖啡馆辨识度。改进重点应在 UI 避让与反馈，不必把场景推翻重画。
- **可见的营业生活感。** 柜台上的机器、顾客手中杯子、爱心和金钱飘字，比只有数字增长的经营界面更有观看价值。
- **手机底部操作区。** “全景 / 选择帮忙 / 管理 / 更多”四项在 390×844 截图上完整、易于区分，没有明显互相挤压；手机经营手账顶部六类入口也保持可读。
- **手账的纸张风格。** 经营面板的纸色、细边框、书签和印章奖励与咖啡馆氛围相配。场景使用像素字、手账使用较传统的中文标题字体属于风格选择，单凭截图不应报成缺陷。
- **结算的利润层级。** 手机结算把 +$86.00 做成最显眼的信息，再补充收入与成本，顺序清楚；应保留这种“先结果、后明细”的处理。

## 环境限制

手机顶部“临时咖啡馆”条占约 76px，确实压缩场景，但它明确提示当前 HTTP 环境不保存进度，不能简单建议隐藏。这属于试玩地址/存档能力的部署体验问题，需由主报告单独说明，不能误报为正式环境的通用画面缺陷。
