# 推荐与口味便笺

目标：让早期菜单就能提供一次明确选择，并让成功送达的推荐在后续营业留下痕迹。

## 推荐

- 原订单加一款同类替代品即可，不再要求额外拥有一款“喜欢”和一款“不喜欢”的菜。保留原单也是主动推荐；“让客人自己选”则不改订单、不发推荐小费。
- 两个选项都需要库存，保持饮品／餐点搭配规则，显示风味、售价和制作时间。选择时再次检查营业状态、队列、菜单和余量，过期按钮不会改已开始制作的订单。
- 每天第一条有条件出现的推荐在正常小事件时间间隔内优先出现；此后具名熟客招呼优先。仍需有可推荐的排队客人，不保证单品菜单、极短营业或无排队时出现。
- 保留既有 12 秒首次等待、20–40 秒后续间隔、14 秒提示期限及暂停规则。打开选择界面后暂停，可慢慢读；忽略仍按原订单营业。此次没有增加每天必须完成的事件。

## 记忆

- 只有普通固定形象顾客记住饮品；12 位故事角色的形象（包括尚未开放故事的角色）保留原偏好和心愿。
- 推荐或试卖的饮品必须实际送达，含喜欢的风味且不含回避风味，才写入口味便笺。只下单、开始制作、取消、缺货及普通自动销售都不产生记忆。
- 每位普通客人最多记住一款饮品。新喜欢的配方替换旧的；再次推荐同一款不会重置初次发现日期。没有好感衰减、额外货币或奖励倍率。
- 再次来访仍使用原客流、形象轮换和组合规则；只替换已有饮品位置，不能给纯餐点订单增加饮品。已上架且有料才点这杯，否则照常点单。
- 具名熟客偏好／米娜心愿、限量试卖都保留既有约束。试卖名额分配后，不允许通过推荐改写该订单；试卖可形成便笺，但要正式上架后才可按记忆常规回点。
- 主动按记忆点单的次数只在实际交付时增加。复点没有新的推荐小费，仍使用正常价格、原料、时间、口碑和熟练度。
- 原来的菜单需求和库存预测仍是估计值；个体回点可能改变实际配比，与具名熟客的偏好替换相同。

## 呈现与存档

交付后有喜欢这杯的想法，回访排队时有再点一次的想法；结算显示当日记忆摘要。熟客记录中的“口味便笺”默认折叠，只展示确实形成记忆的头像、配方、发现日和实际回点次数。

存档版本 22。老存档不从历史销量推测推荐；待送达的推荐随运行快照保存，交付前不会提前记住。无效或丢失运行快照也不会获得进度。已删除自创配方保留当时名称，但不能按记忆出售；同一配方改名保留身份，名称通过安全文本节点显示。
