# B4：上机与存档导入

## 范围

1. **安装包**：安卓 `com.lalaze.tinybeancafe`（调试版、同一把调试钥匙签的发布版，可以互相盖装，存档还在）；iOS 出 Xcode 工程，在模拟器上跑过。名字、图标、启动图和网页版一样，都从 `assets/generated/floor-sample-v1/build/app/` 同步。
2. **存档导入**：存档格式就是网页版的（v27，同一个键）。两条路：
   - 设置 → “搬家”：把这家店的存档复制到剪贴板；从剪贴板导入。导入前说清两家店是谁、第几天、多少钱，确认了才换；每次换下来的店都另存一份（`tiny-bean-cafe/replaced/<时间>`，从不覆盖），列在“搬家”里随时能换回；读不出或写不进去就什么都不改。网页版没有这个界面，所以文字只在 Godot 里。
   - `npm run godot:move`：经 adb 从手机 Chrome（含装成应用的网页版）读出存档，只读不改；加 `--push` 才写进调试版应用：先确认读得到应用的文件，再停应用、读出原来的店、电脑和手机各留一份并读回核对，然后才替换；任何一步拿不准就停，原来的店不动。
3. **自动存档分片**：网页一次写完；这里每帧只写约 1 毫秒，几帧写完，内容和一次写完的逐字相同，中间店里的变化不会混进去。切后台、关游戏、改设置还是一次写完。
4. **手机上的差别**：内存不到 3.5 GB 的手机用半尺寸图；不让屏幕常亮（网页也不）；软键盘只在真的在输入时才让位（系统有时报旧高度）；打包带上文字断行数据，中文才会按词断行。

## 验收

1. `npm run godot:test` 全过，其中 `run_app_tests.gd` 覆盖：分片存档（准备中、营业中逐字相同、半路变化、被一次写完的取代、别处改了存档、没有地方可存、真的自己会存、`lastSeen`、写失败时的提示）和搬家（各种不是存档的文字、更新的版本、保留、每一种写不进去、导入、连着导入两次、同一刻导入、旧的那局不再写、自动重新开店、换回）。
2. `scripts/godot-move-save.test.ts` 过（用本机的 shell 跑发给手机的那些命令，让每一条命令以各种方式失败，原来的店一次都不能丢）；脚本在模拟器的 Chrome 上真读过、`--push` 真写过。
3. `npm run godot:apk`、`npm run godot:apk -- --release`、`npm run godot:ios` 都能出包；包里没有测试，有启动必须的文件。
4. 安卓模拟器（Android 15）上：起名（软键盘）、开店、营业、切后台（开“不保留活动”，进程被杀）回来接着营业、复制再导入、发布版盖装调试版，日志没有错误。
5. iOS 模拟器（iPhone 16，iOS 18.4）上：安装、启动、起名（软键盘）、开店、营业、切后台被杀后回来接着营业，日志没有错误。

## 没有做

- 真机：安卓真机由用户决定什么时候装。iOS 真机要签名（苹果开发者账号），而且要 Xcode 26：4.7.2 官方库用了 iOS 26 SDK 的符号（`CADynamicRange…`、`MTLTensorDomain`），本机 Xcode 16.3 在真机架构上链接不过。官方的模拟器库只有 x86_64，在 Apple 芯片上要用 Rosetta（`ARCHS=x86_64`）。
- 包体：APK 约 195 MB，其中贴图约 170 MB（原尺寸 131、半尺寸 39，都无损）。要上架再压。
- iPhone 上的网页版取不出存档（网页没有导出）。要搬的话得给网页加一个复制按钮，等用户决定。
- 上架（AAB、正式签名钥匙、商店图）。
